# Тестовое задание: Crawler CLI

Разработать CLI-приложение на Go для асинхронного обхода заданного списка сайтов и формирования дерева найденных страниц.

## Требования

Приложение должно:

- принимать список стартовых URL;
- принимать максимальную глубину рекурсивного обхода;
- обходить ссылки только в пределах домена соответствующего стартового URL;
- находить ссылки на каждой HTML-странице;
- получать содержимое тега `<title>`;
- выполнять не более 10 запросов одновременно;
- использовать goroutine и channel;
- предусматривать таймаут отдельного запроса и общий таймаут выполнения;
- пропускать редиректы, не-HTML-ресурсы и недоступные страницы;
- не выполнять повторные запросы для уже посещённого URL;
- предотвращать циклический обход ссылок;
- поддерживать graceful shutdown по `Ctrl+C` через `context.Context`;
- записывать ошибки и HTTP-статусы в отдельный лог-файл;
- сохранять результат обхода в JSON-файл.

Нормализация URL не требуется. При проверке повторов URL сравниваются в том виде, в котором они были получены.

Поддержка авторизации, `robots.txt`, повторных запросов, JavaScript-страниц и infinite scroll не требуется.

## Пример запуска

```bash
crawler-cli \
  --urls https://google.com,https://example.com \
  --depth 3 \
  --timeout 2m \
  --request-timeout 10s \
  --output result.json \
  --log crawler.log
```

## Формат результата

```json
[
  {
    "resource": "https://google.com",
    "title": "Google",
    "links": [
      {
        "resource": "https://google.com/about",
        "title": "About Google",
        "links": []
      }
    ]
  }
]
```

## Дополнительные условия

- параметры запуска не должны быть жёстко заданы в коде;
- ошибка одного ресурса не должна останавливать весь обход;
- конкурентный доступ к общим данным должен быть безопасным;
- количество одновременно работающих goroutine должно быть контролируемым;
- основные компоненты должны быть покрыты unit-тестами;
- репозиторий должен содержать `README.md` с инструкцией по сборке и запуску.
